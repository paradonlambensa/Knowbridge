# KnowBridge — เชื่อมความรู้ เชื่อมคน

แพลตฟอร์มแลกเปลี่ยนทักษะ: คุณสอนสิ่งที่คุณเก่ง แลกกับการเรียนสิ่งที่คุณอยากรู้
จากคนที่เก่งเรื่องนั้น — ไม่มีค่าเรียน มีแต่การแลกกัน

ระบบจับคู่คนสอนกับคนเรียน มีระบบสมาชิก คำขอแลกเปลี่ยน แชทเรียลไทม์ และฟีดชุมชนสำหรับแชร์ความรู้กับทุกคน

> **In short:** a skill-swap platform. Users list what they can teach and what
> they want to learn, search for a match, send an exchange request, and chat in
> real time once it's accepted. A public community feed (posts, #hashtags, likes,
> comments) lets everyone share knowledge. Node.js + Express + MongoDB + Socket.IO,
> with a plain HTML/CSS/JS frontend and no build step.

---

## เส้นทางการใช้งาน

```
สมัครสมาชิก
   ↓
ตั้งโปรไฟล์ — เลือกทักษะที่ "สอนได้" และที่ "อยากเรียน"
   ↓
ค้นหา — หาคนที่สอนทักษะที่เราอยากเรียน (กรองตามชื่อ/หมวดหมู่)
   ↓
ส่งคำขอแลกเปลี่ยน พร้อมข้อความแนะนำตัว
   ↓
อีกฝ่ายเห็นใน Dashboard → ตอบรับ หรือ ปฏิเสธ
   ↓
แชทกันแบบเรียลไทม์ในห้องของคำขอนั้น
```

## ฟีเจอร์

**ระบบสมาชิก**
- สมัคร / เข้าสู่ระบบ / ออกจากระบบ
- รหัสผ่านเข้ารหัสด้วย bcrypt ไม่เก็บเป็นข้อความธรรมดา
- จัดการ session ด้วยคุกกี้ อายุ 24 ชั่วโมง
- กันสมัครซ้ำทั้ง username และ email (ไม่สนตัวพิมพ์เล็ก-ใหญ่ — `Test@x.com` กับ `test@x.com` คืออันเดียวกัน)
- กติกาบัญชี: ชื่อผู้ใช้ 3–20 ตัว (ตัวอักษร ตัวเลข `_ . -`), อีเมลต้องถูกรูปแบบ,
  รหัสผ่านอย่างน้อย 8 ตัวและไม่ใช่รหัสเดาง่ายอย่าง `12345678`
- **เปลี่ยนรหัสผ่าน** ได้ในโปรไฟล์ (ต้องใส่รหัสเดิม) — เครื่องอื่นที่ login ค้างไว้จะถูกออกจากระบบให้
- **ลืมรหัสผ่าน**: ส่งลิงก์ตั้งรหัสใหม่ทางอีเมล (ใช้ได้ 30 นาที ครั้งเดียว) ผ่าน [Resend](https://resend.com)
  ถ้ายังไม่ได้ตั้งระบบส่งอีเมล แอดมินกด "ลิงก์ตั้งรหัสใหม่" ในโปรไฟล์ผู้ใช้ แล้วส่งลิงก์ให้ทางช่องทางอื่นได้
  (ตอนรันในเครื่อง อีเมลจะถูกพิมพ์ออก console แทน) — ตั้งรหัสใหม่แล้วทุกเครื่องของบัญชีนั้นจะถูก logout
- **ยืนยันอีเมล**: สมัครแล้วได้ลิงก์ยืนยันทางอีเมล (ใช้ได้ 24 ชั่วโมง ครั้งเดียว) ขอลิงก์ใหม่ได้ในโปรไฟล์
  ยืนยันแล้วมีป้าย "✓ ยืนยันอีเมล" ในโปรไฟล์สาธารณะ (ไม่แสดงตัวอีเมล) — เปิดใช้เมื่อตั้ง `RESEND_API_KEY`
  (ตอนรันในเครื่องเปิดเสมอ ลิงก์พิมพ์ออก console) ไม่ได้บังคับ ยังไม่ยืนยันก็ใช้งานได้ปกติ
- **เปลี่ยนชื่อผู้ใช้หรืออีเมล** ได้เองในโปรไฟล์ (ใส่รหัสผ่านยืนยัน) — ชื่อในแชทและแจ้งเตือนเก่าเปลี่ยนตาม,
  เปลี่ยนอีเมลแล้วต้องยืนยันอีเมลใหม่ และแจ้งไปที่อีเมลเดิม, เครื่องอื่นที่ login ค้างไว้จะถูกออกจากระบบ
  (เปลี่ยนไปใช้อีเมลที่อยู่ใน `ADMIN_EMAILS` ไม่ได้ กันคนแอบเป็นแอดมิน)

**ข้อมูลส่วนบุคคล (PDPA)**
- หน้า **นโยบายความเป็นส่วนตัว** (`/#privacy` ลิงก์อยู่ท้ายเว็บ) บอกว่าเก็บข้อมูลอะไร ใช้ทำอะไร ใครเห็นอะไร
  ผู้ให้บริการภายนอก ระยะเวลาเก็บ คุกกี้ และสิทธิของเจ้าของข้อมูล
- ตอนสมัครต้องติ๊กยอมรับนโยบาย — บันทึกเวอร์ชันและเวลาที่ยอมรับไว้ในบัญชี
  ผู้ใช้เดิม (หรือเมื่อนโยบายเปลี่ยนเวอร์ชัน) จะเห็นแถบด้านล่างให้อ่านและกด "รับทราบ"
- **ดาวน์โหลดข้อมูลของฉัน** ในโปรไฟล์: ได้ไฟล์ JSON รวมทุกอย่างที่เก็บเกี่ยวกับเรา
  (บัญชี ทักษะ คำขอ ข้อความแชทที่เราส่ง รีวิว โพสต์ ความคิดเห็น ถูกใจ บล็อก รายงาน แจ้งเตือน — ไม่มีรหัสผ่าน)
- **ลบบัญชี** ในโปรไฟล์ (ยืนยันด้วยรหัสผ่าน) ลบจริงทันที กู้คืนไม่ได้: บัญชี โปรไฟล์ ทักษะ โพสต์ ความคิดเห็น ถูกใจ
  คำขอ แชท รีวิวที่ได้รับ แจ้งเตือน บล็อก และ logout ทุกเครื่อง — รีวิวที่เราเขียนให้คนอื่นกับรายงานที่เคยส่ง
  เก็บไว้แบบไม่ระบุตัวตน (คะแนนของอีกฝ่ายไม่หาย และแอดมินยังตรวจรายงานต่อได้) บัญชีทดลองลบไม่ได้
- แก้เนื้อหานโยบายแล้ว ให้เปลี่ยน `PRIVACY_VERSION` ใน `backend/lib/accountData.js` ด้วย ผู้ใช้ทุกคนจะเห็นแถบให้รับทราบใหม่

**ความปลอดภัยและดูแลเนื้อหา**
- **Security headers** (helmet): Content-Security-Policy โหลดสคริปต์/สไตล์/ฟอนต์ได้เฉพาะจากเว็บเราและ Google Fonts,
  ห้ามเว็บอื่นเอาหน้าเราไปฝังใน iframe (กัน clickjacking), HSTS, `X-Content-Type-Options: nosniff` ฯลฯ
- จำกัดจำนวนครั้ง: ใส่รหัสผิดเกิน 10 ครั้งใน 15 นาทีถูกพัก, สมัครได้ 5 ครั้ง/ชม. ต่อ IP,
  โพสต์ 10 ครั้ง/10 นาที, ความคิดเห็น 30 ครั้ง/10 นาที, ส่งคำขอ 20 ครั้ง/ชม., แชท 20 ข้อความ/10 วินาที
- **รายงาน** โพสต์ ความคิดเห็น หรือผู้ใช้ได้ (เลือกเหตุผล + รายละเอียด) — มีคนรายงานไม่ซ้ำกันครบ 3 คน
  เนื้อหานั้นจะถูกซ่อนไว้ก่อนรอแอดมินตรวจ (เจ้าของยังเห็นพร้อมป้ายแจ้ง)
- **บล็อก** ผู้ใช้ได้จากเมนู ⋯ บนโพสต์หรือหน้าโปรไฟล์ — บล็อกแล้วจะไม่เห็นกันทั้งในฟีด ผลค้นหา คู่แนะนำ
  และส่งคำขอ/แชท/แสดงความคิดเห็นหากันไม่ได้ ดูรายชื่อและเลิกบล็อกได้ในโปรไฟล์ของตัวเอง
- **แอดมิน** (กำหนดด้วย `ADMIN_EMAILS`) มีเมนู "แอดมิน" ดูรายงานที่รอตรวจ รวมเป็นรายการละ 1 เรื่อง
  แล้วเลือก "ไม่ผิด" (คืนเนื้อหา) / "ลบเนื้อหา" / "ระงับบัญชี" — บัญชีที่ถูกระงับ login ไม่ได้
  หลุดออกจากระบบทันที และถูกซ่อนจากทุกที่ (ข้อมูลไม่ถูกลบ ปลดระงับได้)

**โปรไฟล์และทักษะ**
- เขียน bio แนะนำตัว
- เลือกทักษะจากแคตตาล็อกกลาง แยกเป็น "สอนได้" กับ "อยากเรียน" ได้ประเภทละสูงสุด 5 ทักษะ
  (ทักษะเดียวกันจะเป็นทั้งสอนและอยากเรียนไม่ได้)
- แคตตาล็อกเริ่มต้น 25 ทักษะ ใน 5 หมวด: IT, Language, Art, Music, Other
- **การ์ดโปรไฟล์** (บริการแยกเขียนด้วย PHP — `card-service/`): รูป SVG มีชื่อ คะแนน แนะนำตัว และทักษะ
  กดได้จากโปรไฟล์สาธารณะและโปรไฟล์ของตัวเอง เอาไปแนบในพอร์ตโฟลิโอหรือแชร์ได้ ใช้แค่ข้อมูลที่เปิดสาธารณะอยู่แล้ว
- **เสนอทักษะใหม่**: ไม่เจอทักษะที่ต้องการ กด "เสนอทักษะใหม่" ในโปรไฟล์ (ชื่อ + หมวด + สอนได้/อยากเรียน)
  แอดมินเห็นในแท็บ "ทักษะที่เสนอ" แก้ชื่อ/หมวดก่อนอนุมัติได้ — อนุมัติแล้วทักษะเข้าแคตตาล็อก
  และเพิ่มเข้าโปรไฟล์คนเสนอให้เลย (ถ้ายังไม่ครบ 5) พร้อมแจ้งเตือน หลายคนเสนอชื่อเดียวกันรวมเป็นคำขอเดียว
  ชื่อทักษะซ้ำกันไม่ได้ (ไม่สนตัวพิมพ์) และเสนอค้างได้ไม่เกิน 5 ทักษะต่อคน

**ค้นหาและจับคู่**
- **คู่แลกเปลี่ยนที่แนะนำ** (หลัง login): คนที่สอนสิ่งที่เราอยากเรียน *และ* อยากเรียนสิ่งที่เราสอน
  ขึ้นก่อนพร้อมป้าย "✨ แลกกันได้พอดี" ตามด้วยคนที่ตรงแค่ทางเดียว
  การ์ดบอกว่าเขาสอนอะไรเราได้ / อยากเรียนอะไรจากเรา และสถานะ (ส่งคำขอแล้ว / เขาส่งมา / กำลังแลกเปลี่ยน)
- กดขอแลกเปลี่ยนจากการ์ดคู่แนะนำ ระบบเขียนข้อความให้จากทักษะที่ตรงกัน
- ช่องค้นหาอยู่บนสุดของหน้า ผลลัพธ์อัปเดตทันทีที่พิมพ์ กรองหมวดหมู่ด้วยปุ่มกดเดียว
- คนที่สอนหลายทักษะขึ้นการ์ดเดียว พร้อมรายการทักษะที่ตรงกับคำค้น
- ผลลัพธ์ไม่แสดงตัวเราเอง

**คำขอแลกเปลี่ยน**
- ส่งคำขอพร้อมข้อความ สถานะเริ่มต้นเป็น `pending`
- หน้า "คำขอของฉัน" แยกแท็บ ได้รับ / ส่งไป พร้อมป้ายสถานะสีของแต่ละคำขอ
- ตอบรับ / ปฏิเสธ และลบคำขอได้ทั้งสองฝ่าย
- **นัดเวลาเรียน**: เลือกวันเวลา + สถานที่/ลิงก์ อีกฝ่ายได้แจ้งเตือน นัดแสดงในการ์ดคำขอและหัวห้องแชท แก้/ยกเลิกได้
- **แลกเปลี่ยนเสร็จแล้ว**: แต่ละฝ่ายกดยืนยัน — ครบทั้งสองฝ่าย สถานะเป็น "เสร็จสิ้น" แล้วจึงให้คะแนนกันได้
  (`pending` → `accepted` "กำลังแลกเปลี่ยน" → `completed` "เสร็จสิ้น" / หรือ `rejected`)

**แชทเรียลไทม์**
- ห้องแชทผูกกับคำขอแลกเปลี่ยนแต่ละรายการ
- ข้อความเข้าทันทีผ่าน Socket.IO และบันทึกลงฐานข้อมูล เปิดใหม่ก็ยังอยู่
- **กำลังพิมพ์…** — อีกฝ่ายเห็นจุดเด้ง ๆ พร้อมชื่อขณะที่เราพิมพ์
- **อ่านแล้ว** — ขึ้นใต้ข้อความล่าสุดของเราที่อีกฝ่ายเปิดอ่านแล้ว อัปเดตทันทีที่เขาเปิดแชท
- **สถานะออนไลน์** — จุดเขียวที่รูปโปรไฟล์ในการ์ดคำขอและหัวแชท / "ใช้งานล่าสุด 5 นาทีที่แล้ว"
  เห็นได้เฉพาะคู่แลกเปลี่ยนที่ตอบรับกันแล้ว ปิดได้ในโปรไฟล์ (เก็บในหน่วยความจำ ไม่บันทึกลงฐานข้อมูล)

**อัปเดตสดทั้งเว็บ (ไม่ต้องรีเฟรช)**
- ฟีดชุมชนมีป้าย "สด" — ตัวเลขถูกใจ/ความคิดเห็นของทุกโพสต์อัปเดตให้ทุกคนที่เปิดอยู่ (รวมคนที่ยังไม่ login)
  เปิดความคิดเห็นค้างไว้ ความคิดเห็นใหม่จะขึ้นเองพร้อมไฮไลต์ โพสต์ที่ถูกลบหายไปทันที
- หน้าแรกนับตัวเลขผู้ใช้/โพสต์/การแลกเปลี่ยนใหม่เองเมื่อมีความเคลื่อนไหว และแสดง "ออนไลน์ตอนนี้ N คน" (ตัวเลขรวม ไม่บอกว่าใคร)
- กดถูกใจแล้วหัวใจเปลี่ยนทันทีโดยไม่รอ server (ถ้าไม่สำเร็จค่อยย้อนกลับ)

**รีวิวและคะแนน**
- ให้คะแนน 1–5 ดาวพร้อมความคิดเห็น **หลังทั้งสองฝ่ายยืนยันว่าแลกเปลี่ยนเสร็จแล้ว** ได้ครั้งเดียวต่อคำขอ
  (กันรีวิวปลอมจากคนที่ไม่ได้เรียนกันจริง)
- คะแนนเฉลี่ยแสดงบนการ์ดผลค้นหา กดดูโปรไฟล์เพื่ออ่านรีวิวทั้งหมดได้

**แจ้งเตือน**
- เด้งแจ้งเตือนทันทีเมื่อมีคำขอใหม่ คำขอถูกตอบรับ/ปฏิเสธ หรือมีข้อความใหม่ — กดที่แจ้งเตือนเพื่อไปยังหน้านั้น
- ตัวเลขบนเมนู Dashboard และบนแท็บเบราว์เซอร์ = คำขอที่รอเราตอบ + ข้อความที่ยังไม่อ่าน
- ปุ่มแชทแต่ละห้องบอกจำนวนข้อความที่ยังไม่อ่าน เปิดแชทแล้วนับว่าอ่านแล้ว
- มีคนถูกใจหรือแสดงความคิดเห็นในโพสต์ของเรา ก็เด้งแจ้งเตือนเหมือนกัน กดแล้วพาไปที่โพสต์นั้น
- **กระดิ่ง 🔔** บน navbar เก็บแจ้งเตือนย้อนหลัง 30 วัน (คำขอ ตอบรับ/ปฏิเสธ นัด ยืนยันเสร็จ ถูกใจ ความคิดเห็น)
  ไม่ได้เปิดเว็บอยู่ตอนนั้นก็ไม่พลาด — มีตัวเลขยังไม่อ่าน กดอ่านทีละรายการหรือ "อ่านทั้งหมด"
  หลายคนถูกใจโพสต์เดียวกันรวมเป็นรายการเดียว "A และอีก 2 คนถูกใจโพสต์ของคุณ"

**หน้าตาและการใช้งาน**
- ดีไซน์ minimal โทนขาว / ฟ้า / น้ำเงิน มี **โหมดมืด** (ปุ่ม 🌙 บน navbar — ถ้าไม่กดเลือกจะตามการตั้งค่าของเครื่อง และจำค่าที่เลือกไว้)
- แต่ละหมวดมีสีประจำ (ไอที น้ำเงิน · ภาษา เขียว · ศิลปะ ชมพู · ดนตรี ม่วง · อื่น ๆ ส้ม) และรูปโปรไฟล์แต่ละคนสีไม่ซ้ำกัน (คำนวณจากชื่อ)
- หน้าแรกแสดงตัวเลขจริงจากฐานข้อมูล (ผู้ใช้ ทักษะ การแลกเปลี่ยน โพสต์) และตัวอย่างการแลกเปลี่ยนให้เห็นภาพทันที
- โครงการ์ดสีเทา (skeleton) ระหว่างโหลด, หัวใจเด้งตอนกดถูกใจ, modal เปิดแบบนุ่ม ๆ — ปิดเองถ้าเครื่องตั้งค่าลดการเคลื่อนไหว
- ส่งลิงก์เว็บใน LINE / Facebook / X แล้วขึ้นการ์ดพร้อมรูป (`frontend/image/og-image.jpg` ขนาด 1200×630)
  server ใส่ URL เต็มของเว็บลงใน meta ให้เอง ย้ายโดเมนก็ไม่ต้องแก้ไฟล์

**ชุมชน (ฟีดสาธารณะ แบบ X)**
- หน้า "ชุมชน" (`/#community`) ให้ทุกคนโพสต์แชร์ความรู้ เคล็ดลับ หรือถามคำถาม ยาวได้ 500 ตัวอักษร
- ใส่ `#แท็ก` ในโพสต์ได้ (รองรับภาษาไทย) กดแท็กเพื่อดูเฉพาะโพสต์ในแท็กนั้น และมีแถบแท็กยอดนิยม 7 วันล่าสุด
- ลิงก์ในโพสต์กดได้ เปิดแท็บใหม่
- กด ♥ ถูกใจ (กดซ้ำ = ยกเลิก) และแสดงความคิดเห็นใต้โพสต์ ลบโพสต์/ความคิดเห็นของตัวเองได้
- มีคนโพสต์ใหม่ระหว่างอ่าน จะขึ้นปุ่ม "มีโพสต์ใหม่ N โพสต์" ให้กดโหลด ไม่ดันฟีดเลื่อนเอง
- โหลดโพสต์เก่าเพิ่มทีละหน้า และหน้าโปรไฟล์ของแต่ละคนแสดงโพสต์ล่าสุด 3 โพสต์
- คนที่ยังไม่ login อ่านฟีดได้ แต่ต้อง login ก่อนโพสต์ ถูกใจ หรือแสดงความคิดเห็น

## เทคโนโลยีที่ใช้

| ส่วน | ใช้อะไร |
|---|---|
| Runtime | Node.js |
| เว็บเซิร์ฟเวอร์ | Express 5 |
| ฐานข้อมูล | MongoDB Atlas (ใช้ไดรเวอร์ `mongodb` ตรง ๆ ไม่ผ่าน ODM) |
| Session | `express-session` + `connect-mongo` (เก็บใน MongoDB ไม่หายตอน restart) |
| เข้ารหัสรหัสผ่าน | `bcryptjs` |
| ความปลอดภัย | `helmet` (security headers), `express-rate-limit` |
| เรียลไทม์ | `Socket.IO` |
| หน้าเว็บ | HTML + CSS + JavaScript ล้วน ไม่มีเฟรมเวิร์ก ไม่ต้อง build |
| การ์ดโปรไฟล์ | PHP 8.4 + Apache (Docker) — บริการแยก เรียก API ของเว็บหลัก |

## วิธีรัน

ต้องมี Node.js และฐานข้อมูล MongoDB (ใช้ [MongoDB Atlas](https://www.mongodb.com/atlas) ฟรีได้)

```bash
git clone https://github.com/paradonlambensa/Knowbridge.git
cd Knowbridge
npm install
```

สร้างไฟล์ `.env` ที่รากโปรเจค:

```env
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority
SESSION_SECRET=ใส่ค่าสุ่มยาว ๆ ของคุณเอง
PORT=3000
MONGODB_DB=knowbridge_dev
```

| ตัวแปร | จำเป็น | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `MONGODB_URI` | ✅ | — | ไม่มีตัวนี้เชื่อมฐานข้อมูลไม่ได้ |
| `SESSION_SECRET` | ⚠️ | `knowbridge-secret-2024` | **ต้องตั้งเองก่อนใช้งานจริง** ค่าเริ่มต้นอยู่ในโค้ดสาธารณะ ใครก็ปลอม session ได้ |
| `PORT` | ❌ | `3000` | |
| `ADMIN_EMAILS` | ❌ | — | อีเมลแอดมิน คั่นด้วย `,` เช่น `me@gmail.com,friend@gmail.com` |
| `DEMO_ACCOUNTS` | ❌ | เปิดในเครื่อง / ปิดบน Render | `on` หรือ `off` — เปิด/ปิดบัญชีทดลอง 3 บัญชี (ปิด = login ไม่ได้และถูกซ่อน แต่ข้อมูลยังอยู่) |
| `RATE_LIMIT` | ❌ | เปิด | ตั้ง `off` เพื่อปิดการจำกัดจำนวนครั้ง (ใช้ตอนเทสเท่านั้น) |
| `RESEND_API_KEY` | ❌ | — | API key จาก [Resend](https://resend.com) สำหรับส่งอีเมลลืมรหัสผ่านและยืนยันอีเมล (ไม่ตั้ง = แอดมินสร้างลิงก์รีเซ็ตให้แทน และไม่มีการยืนยันอีเมล) — ยังไม่ยืนยันโดเมนกับ Resend จะส่งได้แค่อีเมลเจ้าของบัญชี Resend |
| `MAIL_FROM` | ❌ | `KnowBridge <onboarding@resend.dev>` | ผู้ส่งอีเมล — ต้องเป็นโดเมนที่ยืนยันใน Resend แล้ว |
| `APP_URL` | ❌ | ดูจาก request | URL ของเว็บที่ใช้สร้างลิงก์ในอีเมลและการ์ดแชร์ลิงก์ เช่น `https://knowbridge.onrender.com` |
| `CARD_SERVICE_URL` | ❌ | — | URL ของบริการการ์ด (PHP) เช่น `https://knowbridge-card.onrender.com` — ไม่ตั้ง = ซ่อนปุ่มการ์ดโปรไฟล์ |
| `CONTACT_EMAIL` | ❌ | — | อีเมลติดต่อเรื่องข้อมูลส่วนบุคคล แสดงในหน้านโยบาย (ไม่ตั้ง = แสดงเป็น "ทีมผู้พัฒนาโครงงาน") |
| `MONGODB_DB` | ❌ | `knowbridge` | ชื่อฐานข้อมูลใน cluster — **ตอนรันในเครื่องให้ตั้งเป็นชื่ออื่น** (เช่น `knowbridge_dev`) ถ้าใช้ cluster เดียวกับเว็บจริง จะได้ไม่ไปเขียนทับข้อมูลจริง |

แล้วสั่ง:

```bash
npm start
```

เปิด http://localhost:3000

ฐานข้อมูลจะถูก seed ให้อัตโนมัติตอนเชื่อมต่อครั้งแรก โดยข้ามให้เองถ้ามีข้อมูลอยู่แล้ว

### เทส

```bash
npm test
```

เปิด server ให้เองกับฐานข้อมูล `knowbridge_test` (เปลี่ยนได้ด้วย `TEST_DB`) แล้วไล่เทส flow ทั้งหมด:
สมัคร → ค้นหา → ส่งคำขอ → ตอบรับ → แชท → แจ้งเตือน → รีวิว → ฟีดชุมชน รวมถึงเคสความปลอดภัย
(คนนอกอ่านแชทไม่ได้, ปลอมผู้ส่ง/ผู้ถูกรีวิวไม่ได้), ดาวน์โหลดข้อมูล / ลบบัญชี (ข้อมูลหายครบ ตัวนับถูกต้อง),
เสนอทักษะ → แอดมินอนุมัติ, ยืนยันอีเมล (ดึงลิงก์จาก console ของ server), เปลี่ยนชื่อผู้ใช้/อีเมล
และ session ที่ต้องอยู่รอดหลัง restart server
สร้างบัญชีใหม่ทุกครั้ง รันซ้ำได้โดยไม่ต้องล้างข้อมูล — ถ้าจะเทสกับ server ที่เปิดอยู่แล้วให้ตั้ง `BASE_URL`

ถ้าเครื่องมี PHP ตั้ง `PHP_BIN` (path ของ php) แล้ว `npm test` จะเปิดบริการการ์ดด้วย `php -S` แล้วเทสการ์ดกับข้อมูลจริงให้ด้วย
ส่วนเทสการวาดการ์ดอย่างเดียว (ไม่ต้องต่อฐานข้อมูล):

```bash
php card-service/tests/run.php
```

## ข้อมูลตัวอย่าง

ตอนรันครั้งแรกกับฐานข้อมูลเปล่า ระบบจะใส่ให้:

- **25 ทักษะ** ใน 5 หมวด (IT, Language, Art, Music, Other)
- **บัญชีทดลอง 3 บัญชี** รหัสผ่าน `demo1234` ทุกบัญชี
  | Email | Username | ทักษะ |
  |---|---|---|
  | `lxzy@demo.com` | Lxzywinn | สอน Python · อยากเรียน English |
  | `opie@demo.com` | Opie | สอน English · อยากเรียน JavaScript |

### ข้อมูลตัวอย่างสำหรับวันพรีเซนต์

เว็บที่เพิ่งเปิดยังโล่ง — ใส่ผู้ใช้ โพสต์ และการแลกเปลี่ยนที่ดูเหมือนใช้งานจริงได้ด้วยคำสั่งเดียว แล้วลบทิ้งได้ทั้งหมดหลังพรีเซนต์

```bash
npm run demo:add -- --db=knowbridge
```

```bash
npm run demo:remove -- --db=knowbridge
```

- ใช้ `MONGODB_URI` ใน `.env` และต้องใส่ชื่อฐานข้อมูลด้วย `--db` ทุกครั้ง (เว็บจริงบน Render ใช้ `knowbridge`)
- สร้างผู้ใช้ตัวอย่าง 10 คน พร้อมทักษะ, โพสต์ 12 โพสต์ (มีแท็ก ถูกใจ ความคิดเห็น), การแลกเปลี่ยนที่เสร็จแล้วพร้อมรีวิว,
  การแลกเปลี่ยนที่กำลังคุยและนัดกันอยู่ และคำขอที่รอตอบ — ผู้ใช้ตัวอย่าง login ไม่ได้ (รหัสผ่านสุ่ม)
- ถ้ามีบัญชีทดลองในฐานข้อมูล จะมีของรอโชว์ให้ด้วย: `Lxzywinn` มีคำขอใหม่ (ขึ้นในกระดิ่ง), แชทที่มีนัดพรุ่งนี้
  พร้อมข้อความยังไม่อ่าน และการแลกเปลี่ยนที่เสร็จแล้วรอให้คะแนน — ตั้ง `DEMO_ACCOUNTS=on` แล้ว login ด้วย `lxzy@demo.com`
- `demo:remove` ลบผู้ใช้ตัวอย่างแบบเดียวกับการลบบัญชี จึงลบสิ่งที่คนจริงทำกับข้อมูลตัวอย่างไปด้วย
  (เช่น แชทในคำขอที่มีผู้ใช้ตัวอย่าง) ข้อมูลอื่นของผู้ใช้จริงไม่ถูกแตะ — รันซ้ำได้ ถ้ามีอยู่แล้ว `demo:add` จะไม่ใส่ซ้ำ

## Socket.IO

| ทิศทาง | Event | Payload | ทำอะไร |
|---|---|---|---|
| client → server | `joinRoom` | `requestId` | เข้าห้องแชท — เฉพาะคู่กรณีของคำขอที่ตอบรับแล้ว |
| client → server | `sendMessage` | `{ requestId, text }` | บันทึกข้อความลง DB แล้วกระจายให้ทุกคนในห้อง (ผู้ส่งอ่านจาก session) |
| client → server | `typing` | `requestId` | บอกอีกฝ่ายในห้องว่ากำลังพิมพ์ (server ส่งต่อไม่ถี่กว่า 1 ครั้ง/วินาที) |
| server → client | `newMessage` | ข้อความที่บันทึกแล้ว | มีข้อความใหม่เข้าห้อง |
| server → client | `notify` | `{ _id, type, from, request_id?, post_id?, preview?, schedule_at?, count?, at }` | แจ้งเตือน — `type`: `request`, `accepted`, `rejected`, `message`, `like`, `comment`, `schedule`, `complete_request`, `completed` |
| server → client | `chatError` | ข้อความ | ส่งแชทไม่ได้ (ถี่เกินไป หรือมีการบล็อก) |
| server → client | `feed:new` | `{ post_id, author_id }` | มีโพสต์ใหม่ในฟีด |
| server → client | `feed:counts` | `{ post_id, like_count?, comment_count? }` | ตัวเลขถูกใจ/ความคิดเห็นของโพสต์เปลี่ยน (ตัวเลขอย่างเดียว ไม่บอกว่าใคร) |
| server → client | `feed:delete` | `{ post_id }` | โพสต์ถูกลบ |
| server → client | `stats` | `{ users, skills, posts, exchanges, online }` | ตัวเลขหน้าแรกเปลี่ยน (รวบเป็นครั้งเดียวทุก 2 วินาที) |
| server → client | `presence:count` | `{ online }` | จำนวนคนที่ออนไลน์เปลี่ยน |
| server → client | `presence` | `{ user_id, online, last_seen, hidden? }` | คู่แลกเปลี่ยนออนไลน์/ออฟไลน์ (ส่งถึงคู่แลกเปลี่ยนเท่านั้น) |
| server → client | `typing` | `{ request_id, user_id, name }` | อีกฝ่ายในห้องกำลังพิมพ์ |
| server → client | `chat:read` | `{ request_id, user_id, at }` | มีคนในห้องอ่านแชทถึงเวลา `at` แล้ว |

คนที่ยังไม่ login ต่อ socket ได้ แต่ได้แค่อัปเดตสาธารณะ (`feed:*`, `stats`, `presence:count`) — เข้าห้องแชท ส่งข้อความ
หรือรู้สถานะออนไลน์ของใครไม่ได้ ส่วนทุก socket ของคนที่ login จะอยู่ในห้อง `user:<id>` แจ้งเตือนจึงไปถึงทุกแท็บที่เปิดอยู่

## Deploy

deploy ขึ้น [Render](https://render.com) ได้ฟรีผ่านไฟล์ `render.yaml` ที่รากโปรเจค
(web service แบบ free, region `singapore`, ใช้ Node 24.x ตาม `engines` ใน `package.json` — ล็อกไว้ให้ตรงกับที่เทส)

1. push โค้ดขึ้น GitHub
2. ใน Render Dashboard เลือก **New → Blueprint** แล้วเลือก repo นี้
3. กรอก `MONGODB_URI` ตอนที่ Render ถาม — `SESSION_SECRET` ระบบสุ่มให้เอง
   และเพิ่ม `ADMIN_EMAILS` (อีเมลของคุณ) ใน Environment ถ้าต้องการเมนูแอดมิน
4. ใน MongoDB Atlas → **Network Access** เพิ่ม `0.0.0.0/0` เพราะ IP ขาออกของ Render free ไม่คงที่

ไฟล์ `.env` ไม่ได้ถูก commit ขึ้นมาด้วย ค่าทั้งหมดตั้งใน Environment ของ Render

> ⚠️ แผน free จะหลับเมื่อไม่มีคนเข้าราว 15 นาที เปิดครั้งแรกหลังหลับจะช้าประมาณ 1 นาที
> (session เก็บใน MongoDB ผู้ใช้จึงไม่หลุด login ตอนระบบหลับ)

### การ์ดโปรไฟล์ (บริการ PHP)

`render.yaml` มี service ที่สอง `knowbridge-card` (Docker + PHP 8.4 + Apache) — push แล้ว Render สร้างให้จาก Blueprint
(ถ้าไม่สร้างเอง: Dashboard → Blueprints → เลือก Blueprint นี้ → **Sync**) ตั้ง `KNOWBRIDGE_API_URL` เป็น URL ของเว็บหลักไว้แล้ว

1. รอ `knowbridge-card` deploy เสร็จ แล้วคัดลอก URL ของมัน (เช่น `https://knowbridge-card-xxxx.onrender.com`)
2. เว็บหลัก `knowbridge` → **Environment** → เพิ่ม `CARD_SERVICE_URL` = URL นั้น → Save and deploy
3. ปุ่ม "🪪 ดูการ์ดโปรไฟล์" จะขึ้นในโปรไฟล์ — หรือเปิด URL ของบริการการ์ดตรง ๆ แล้ววางลิงก์โปรไฟล์

ทั้งสอง service ใช้แผนฟรี (หลับเมื่อไม่มีคนใช้) — เปิดการ์ดครั้งแรกหลังหลับอาจช้าราว 1 นาที
ส่วนเว็บหลักไม่ได้รอบริการการ์ด ถ้าบริการการ์ดล่ม เว็บหลักก็ยังใช้ได้ปกติ

รันในเครื่อง (ต้องมี PHP 8.4 และเปิดเว็บหลักไว้ที่พอร์ต 3000):

```bash
cd card-service && KNOWBRIDGE_API_URL=http://localhost:3000 php -S localhost:8080 -t public
```

แล้วตั้ง `CARD_SERVICE_URL=http://localhost:8080` ใน `.env` ของเว็บหลัก

### ใช้โดเมนของตัวเอง

1. ซื้อโดเมน (เช่น `knowbridge.xyz`) จากผู้ขายโดเมนเจ้าไหนก็ได้
2. Render → service → **Settings → Custom Domains → Add** ใส่โดเมน แล้วเพิ่ม DNS ตามที่ Render บอก
   (`@` เป็น A record ไปที่ IP ของ Render, `www` เป็น CNAME ไปที่ `<ชื่อ service>.onrender.com`) — Render ออกใบรับรอง HTTPS ให้เอง
   ถ้าใช้ DNS ของ Cloudflare ให้ตั้งเป็น **DNS only** (เมฆสีเทา)
3. Resend → **Domains → Add Domain** ใส่โดเมนเดียวกัน เพิ่ม DNS (MX + TXT) ตามที่ Resend บอก แล้วกด Verify
4. Render → **Environment**: `APP_URL=https://โดเมน`, `MAIL_FROM=KnowBridge <noreply@โดเมน>`, `RESEND_API_KEY=re_...` → Save and deploy

### สำรองและกู้คืนข้อมูล

```bash
npm run backup -- --db=knowbridge
```

ได้โฟลเดอร์ `backups/knowbridge-<วันเวลา>/` (ไฟล์ JSON 1 ไฟล์ต่อ collection + `meta.json`) — เก็บชนิดข้อมูลไว้ครบ
(ObjectId, วันที่) ไม่สำรอง session และลิงก์ชั่วคราว

```bash
npm run restore -- --from=backups/knowbridge-2026-10-05-1530 --db=knowbridge_restore
```

ปลายทางต้องว่าง ถ้าจะทับข้อมูลเดิมใส่ `--replace` (ลบข้อมูลใน collection เหล่านั้นก่อน) — กู้คืนลงฐานข้อมูลของเว็บแล้ว
ให้ restart server (Render: Manual Deploy)

> ⚠️ ไฟล์สำรองมีอีเมลและ hash ของรหัสผ่านผู้ใช้ — `backups/` อยู่ใน `.gitignore` ห้ามอัปขึ้นที่สาธารณะ
> และลบไฟล์เก่าที่ไม่ใช้แล้วทิ้ง Atlas แบบฟรี (M0) ไม่มี backup อัตโนมัติ ควรสำรองก่อนแก้อะไรใหญ่ ๆ หรือก่อนพรีเซนต์
